Comparison

WorkRoom vs Buzz

Both products put people and agents in the same rooms, and both speak ACP and MCP. The difference is what the room accumulates: Buzz treats the signed event log as the memory; WorkRoom treats distilled, channel-owned knowledge as a first-class thing the room holds.

Side by side

Buzz is a self-hostable team workspace on the Nostr protocol, built at Block, Inc. — with chat, a git forge, workflows, and voice. WorkRoom is deliberately narrower: channels, memory, and the record.

Where Buzz is genuinely strong

A credible comparison admits what the other side does better.

Cryptographic everything

Every message, reaction, workflow step, and git push is a signed event with a hash-chained audit trail. Per-event attribution is built into the substrate, not layered on top.

The workspace is the forge

Built-in git hosting on object storage, branches as channels, patches and reviews as first-class events. WorkRoom explicitly stays out of code hosting.

Breadth and maturity

Desktop, web, mobile, CLI, voice — plus formally verified multi-tenancy and real production mileage inside Block. Buzz is much further along.

Where WorkRoom is different

Knowledge, not just history

A searchable log answers "what happened." WorkRoom's channel memory answers "what do we know" — distilled entries with trust levels and provenance, pushed to the agent before every turn, not just findable after the fact.

Memory belongs to the room

Buzz's engrams are encrypted to one agent–owner pair; when either leaves, the knowledge leaves. In WorkRoom the channel owns the memory, so a colleague's different agent starts where yours stopped.

Three seams, one server

WorkRoom is a Rails app, a desktop client, and your local agent — no relay, no Redis, no event protocol to operate. Self-host in one command, or run nothing at all: the hosted workspace is a signup, free for small teams.

Which one fits

Choose WorkRoom if…

  • The expensive problem is knowledge evaporating between sessions and people
  • You want shared memory with trust levels and provenance, not a log to dig through
  • Agents must stay local under each person's own credentials, with no planned exception
  • You prefer one small system you can read end-to-end over a platform
  • You want to start today on a hosted workspace — free for small teams — instead of operating infrastructure

Choose Buzz if…

  • You want chat, code hosting, CI visibility, and automation in one event log
  • Cryptographic per-event attribution and tamper-evident audit are requirements
  • You need a proven, multi-tenant deployment with formal isolation guarantees
  • Your team is ready to operate a Nostr relay stack (Postgres, Redis, MinIO)
